# 사전 생성 원석 주얼리 이미지 설계

- 작성일: 2026-09-13 (Asia/Seoul)
- 상태: 승인됨
- 적용 범위: Phase 1 기본 추천 결과와 같은 원석 이미지 URL을 사용하는 후속 화면
- 관련 요구사항: FR-BASIC-005~010, NFR-PERF-001~002, NFR-A11Y-001
- 관련 화면: S05, S08, S12, S13, S14

## 목적

추천 결과에서 원석 표본 사진 대신 해당 원석을 세팅한 목걸이 이미지를 보여준다. 이미지 생성은 개발 시점에 한 번만 수행하고, 런타임에는 검수된 정적 자산을 제공한다. 추천 엔진의 원석 선택과 결정론은 변경하지 않는다.

## 결정 사항

### 제작 방향

- 활성 원석 23종마다 주얼리 이미지 한 장을 만든다.
- 모든 주얼리는 자연스러운 원석별 카보숑과 통일된 925 실버 베젤·체인을 사용한다.
- 원석의 자연스러운 형태, 색, 무늬, 투명도는 원석별 특성에 맞춘다. 모든 원석을 동일한 물방울형으로 강제하지 않는다.
- 배경, 조명, 촬영 거리, 구도는 하나의 컬렉션처럼 일관되게 유지한다.
- 이미지는 정사각형이며, 펜던트를 중앙 안전 영역에 배치해 128px 원형 크롭에서도 원석과 목걸이임을 식별할 수 있게 한다.
- 사람, 손, 포장재, 다른 보석, 문구, 로고, 워터마크, 과도한 판타지 광원은 포함하지 않는다.

### 생성과 검수

- 각 원석은 독립된 프롬프트와 독립된 이미지 생성 호출로 제작한다.
- 프롬프트에는 검수된 원석 이름, 대표 색, 시각적 재질 특성만 사용한다. 사용자의 소원, 감정, 자유 입력, 생년월일시, 관계 정보는 이미지 생성에 전달하지 않는다.
- 생성물은 다음 기준으로 육안 검수한다.
  - 원석의 대표 색·무늬·투명도 식별 가능
  - 실버 펜던트 목걸이 형태 식별 가능
  - 중앙 원형 크롭에서 핵심 피사체가 잘리지 않음
  - 금지 요소가 없음
  - 실제 제품 사진처럼 오해를 유발하는 브랜드·가격·구매 표현이 없음
- 기준을 충족하지 못한 원석만 한 가지 문제를 명시해 다시 생성한다.

## 자산과 데이터 계약

- 최종 자산 경로는 `public/images/jewelry/{stone-slug}.png`로 통일한다.
- 파일명은 `prisma/seed-data/stones.json`의 slug와 정확히 일치시킨다.
- `Stone.imageUrl`의 데이터 타입과 API 응답 구조는 변경하지 않는다.
- `prisma/seed-data/stones.json`의 `imageUrl`만 `/images/jewelry/{stone-slug}.png`로 교체한다.
- 기존 `public/images/stones/` 원석 사진은 삭제하거나 덮어쓰지 않는다.
- 런타임 이미지 생성 API, 이미지 생성 큐, 별도 이미지 테이블, 외부 CDN은 추가하지 않는다.

## 화면 동작

- S05 기본 추천 결과는 기존 `StoneAvatar`를 통해 주얼리 이미지를 표시한다.
- S08 오행 결과, S12 관계 결과, S13 공유 화면, S14 보관함 등 동일한 `Stone.imageUrl`을 사용하는 화면에도 같은 주얼리 이미지가 표시된다.
- 이미지 대체 텍스트는 `"{원석명} 실버 펜던트 목걸이"` 형식으로 제공한다.
- 이미지 URL이 없으면 기존 `colorHex` 기반 원형 fallback을 표시한다.
- 이미지 로딩 자체가 실패해도 색상 fallback으로 전환한다.
- 결과 화면에는 `AI로 생성한 주얼리 예시 이미지이며 실제 판매 상품이 아니에요.`라는 안내를 이미지 가까이에 제공한다.

## 오류 처리와 성능

- 정적 이미지가 누락되면 빌드 전 자산 무결성 테스트가 실패해야 한다.
- 브라우저에서 이미지 로딩이 실패해도 추천 내용과 CTA는 계속 이용할 수 있어야 한다.
- 이미지 생성은 개발 시점에만 수행하므로 추천 API의 응답시간, 재시도 정책, LLM fallback 흐름에는 영향을 주지 않는다.
- 추천 엔진 입력·점수·tie-break·`rulesetVersion`은 변경하지 않는다.

## 테스트와 수용 기준

### 자동 테스트

- 활성 원석 23종의 slug에 대응하는 PNG 파일이 모두 존재한다.
- 모든 주얼리 `imageUrl`이 `/images/jewelry/{slug}.png` 형식이고 실제 파일과 일치한다.
- `StoneAvatar`는 전달받은 구체적인 대체 텍스트를 렌더링한다.
- 이미지 URL이 없거나 이미지 로딩에 실패하면 `colorHex` fallback이 표시된다.
- 추천 조회 API는 선택된 원석의 주얼리 이미지 URL을 반환한다.
- TypeScript strict 검사, lint, 관련 단위·API 테스트와 핵심 결과 화면 E2E가 통과한다.

### 육안 검수

- 23개 이미지 각각이 제작·검수 기준을 충족한다.
- 128px 원형 표시와 모바일 결과 화면에서 원석 및 목걸이 형태를 알아볼 수 있다.
- 이미지 컬렉션의 배경, 조명, 금속 색, 구도 편차가 제품 경험을 해치지 않는다.

## 개인정보와 AI 안전

- 이미지 생성 입력에는 원석 카탈로그 정보 외의 사용자 데이터를 포함하지 않는다.
- LLM 또는 이미지 모델은 원석을 선택하거나 추천 결과를 변경하지 않는다.
- 생성 이미지와 안내 문구는 의료·심리 진단, 치료·예방 효과, 미래 예언, 결과 보장, 결정론적 궁합 표현을 포함하지 않는다.
- 이미지 생성 실패는 추천 실패로 취급하지 않으며, 검수된 정적 자산이 준비되지 않은 상태로 배포하지 않는다.

## 비범위

- 추천 요청마다 새로운 이미지 생성
- 사용자 입력에 따른 주얼리 디자인 개인화
- 반지, 귀걸이, 팔찌 등 목걸이 외 제품군
- 구매 링크, 가격, 재고, 장바구니 등 커머스 기능
- 기존 추천 점수식, 규칙 엔진, LLM 카피 생성 변경
